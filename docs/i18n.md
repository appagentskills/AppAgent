# Internationalization (i18n): contributor guide

AppAgent's UI ships in English (`en`) plus 24 languages: ar, pt-BR, zh-CN, zh-TW, cs, da, nl, fi, fr, fr-CA, de, he, hu, it, ja, ko, nb, pl, pt-PT, ru, es, sv, th, tr (`I18N_LANGUAGES`). This guide describes the API as implemented.

| Layer | File | Runs in |
|---|---|---|
| Runtime core | `src/js/core/025-i18n.js` | panel page **and** service worker (`WORKER_SHARED_FILES`) |
| DOM layer | `src/js/ui/245-i18n-dom.js` | panel page only |
| Catalogs | `src/locales/<code>.json`, copied to `locales/<code>.json` by both builds | fetched at runtime |
| Extractor / checker | `build/i18n-extract.js` | Node, tests, `run_js_file` (sandbox-safe) |
| RTL overrides | `src/css/26-rtl.css` | panel page |
| Tests | `test/i18n.test.js`, `test/i18n-dom.test.js`, `test/i18n-extract.test.js`, `test/i18n-prompt.test.js` | |

## 1. Keys are the English text (gettext style)

The key **is** the exact English UI string. With no catalog (English, or a missing translation) every call returns the English source, so English is the identity and tests asserting English keep passing.

### `t(source, params)`

- `{name}` placeholders are filled from `params`' own properties; a missing / `null` / `undefined` param stays verbatim (`{name}`). Never throws.
- One call per **whole sentence**, punctuation inside. Never concatenate translated fragments (word order differs between languages).
- Keys must be plain single- or double-quoted literals: no template literals, variables or concatenations (the extractor cannot see them).

```js
// Wrong: fragments, and a key the extractor cannot read
msg = t('Deleted') + ' ' + name + ' ' + t('from') + ' ' + repo;
msg = t(`Deleted ${name}`);
// Right: one sentence with placeholders
msg = t('Deleted {name} from {repo}.', { name: name, repo: repo });
```

`t()` returns plain text. Keep the escaping the original code had: if it escaped a dynamic part before putting it into HTML, escape that param the same way. Never put raw `t()` output inside a JS string literal of an inline `on*=` handler; call `t()` inside the handler, or use the file's existing escaper.

### `tn(count, one, other, params)`: plurals

- The key is `other` (the English plural form). `{count}` is auto-filled with `i18nFormatNumber(count)` unless you pass `params.count`.
- English fallback: `Number(count) === 1 ? one : other`.
- A catalog value is either a string (same text for every count) or an object keyed by the target language's CLDR plural categories (`zero`, `one`, `two`, `few`, `many`, `other`; chosen with `Intl.PluralRules` for `i18nLocale()`). `other` is required.

```js
// before: n + (n === 1 ? ' file' : ' files')
label = tn(n, '{count} file', '{count} files');
```

```json
"{count} files": { "one": "{count} plik", "few": "{count} pliki", "many": "{count} plików", "other": "{count} pliku" }
```

### `N_(s)`: label maps

`N_(s)` returns `s` unchanged; it only marks the string for extraction. Use it for maps whose values are **also** sent to the model, stored or compared (for example display-name maps that feed the English "DISABLED CAPABILITIES" line of the system prompt). Keep the value English in logic and translate at display time:

```js
var STATUS_LABELS = { running: N_('Running'), done: N_('Done') };
badge.textContent = t(STATUS_LABELS[state]);   // display only
```

## 2. Markup: `data-i18n` and `data-i18n-attr`

`applyI18n(root)` (ui/245) translates markup under `root` (default `document`):

- `data-i18n`: each **own** non-whitespace text node of the element is translated. Child elements (icons, `<kbd>`, nested spans) are untouched, and the node's leading/trailing whitespace is kept.
- `data-i18n-attr="title,placeholder,aria-label"`: the listed attributes are translated.
- Originals are stored on the element, so re-applying after a language switch works.
- **Key rule** (shared by the DOM layer and the extractor): entities decoded, whitespace runs collapsed to one space, trimmed, i.e. `normalizeI18nKey(decodeHtmlEntities(text))` in `build/i18n-extract.js`, the same rule as `i18nNormalizeKey` in ui/245. `<span data-i18n>Save &amp;\n   close</span>` has the key `Save & close`.

```html
<button data-i18n data-i18n-attr="title,aria-label" title="New chat" aria-label="New chat"><svg>…</svg> New chat</button>
```

`applyI18n(document)` runs at boot and after every language switch. Markup inserted later must either use `t()` while the string is built (preferred in JS) or call `applyI18n(container)` after insertion. Markup whose text is dynamic (`'<span data-i18n>' + name + '</span>'`) cannot be extracted (the extractor lists it in `.nonLiteral`); use `t()` with a placeholder instead.

## 3. Dates, numbers, relative time

- `toLocaleDateString()` / `toLocaleTimeString()` / `toLocaleString()` / `Number#toLocaleString()` become `i18nFormatDate` / `i18nFormatTime` / `i18nFormatDateTime` / `i18nFormatNumber(value, opts)`. They use `Intl` with `i18nLocale()`: `null`/`''` gives `''`, invalid input gives `String(value)`, and bad `opts` are retried without options.
- Hand-rolled "5m ago" UI text becomes `i18nFormatRelative(date, { now, style, numeric })`: `style` is `'short'` (default), `'long'` or `'narrow'`; `numeric` is `'auto'` (default, "yesterday") or `'always'` ("1 day ago"); `now` is the reference time (useful in tests).
- Model-facing text (tool results, the system prompt's `CURRENT DATE`, which stays en-US) keeps its English formatting.

## 4. Language resolution and switching

- **Preference:** IDB setting `uiLanguage` = `'auto'` (default) or a language code. It is mirrored to appStorage (`uiLanguage` / `uiLanguageDir`) so `src/html/head.html` sets `<html lang dir>` at first paint.
- **`resolveI18nLanguage(pref, browserLangs)`** (pure): exact match first, then pt→pt-BR, zh / zh-Hans→zh-CN, zh-Hant / zh-HK→zh-TW, no / nn→nb, fr-CA→fr-CA, other fr-*→fr, other xx-YY→xx, else `en`. `'auto'` resolves against the browser languages.
- **`i18nLang()` / `i18nLocale()` / `i18nDir()`:** the active code, its BCP-47 locale and `'rtl'` / `'ltr'`. `i18nLocale()` is the code, except that a base-only code (en, fr, de…) takes the first browser tag of the same language, so en-GB users keep UK date formats.
- **`await i18nInit(opts)`:** reads the setting, resolves it, fetches `locales/<code>.json` (never for `en`; cached and deduped) and activates it. Falls back to English on failure, never throws, returns the active code; only the latest call activates. `opts` `{language, browserLanguages}` override the setting and `navigator.languages`. `i18nSetCatalog(code, obj)` injects a catalog (`null` deletes it).
- **Boot:** core/120 starts `i18nInit()` early, then awaits `i18nBootApply()` with that promise: a bounded wait (`I18N_BOOT_DEADLINE_MS` = 3 s) for it and the IDB preference, then `i18nApplyCurrent()` (appStorage mirror, `<html lang dir>`, `applyI18n(document)`). When the wait times out (wedged IDB), the late load re-applies and calls `refreshI18nViews()`.
- **Settings → Language** (`#settings-language-select`, options from `i18nLanguageOptionsHtml`): "Auto (browser language)" plus the 25 languages; `onchange` calls `setAppLanguage(code)`.
- **Quick settings (gear panel) → Language** (`#settings-panel-language` in `src/html/body.html`): the same picker in the header gear dropdown. It shares the option list (`i18nLanguageOptionsHtml`), the preference (`appLanguagePref` / IDB `uiLanguage`) and the handler (`onchange` → `setAppLanguage(code)`), so RTL, locale formatting and the agent reply language behave identically. `syncSettingsPanelLanguage()` (ui/245) refills it on panel open (`toggleSettingsPanel`, ui/130) and at the end of every switch (`refreshI18nViews()`), while the settings page re-renders its own select from the same preference, so the two pickers always show the same value.
- **A switch RE-RENDERS; it never reloads the panel.** `setAppLanguage(code)` (serialized, so rapid switches can't finish out of order) persists IDB `uiLanguage`, updates the appStorage mirror and `<html lang dir>`, runs `i18nInit({language: pref})` (the explicit preference, so no IDB re-read), then `refreshI18nViews()`, and finally posts `{type: 'ui-language', uiLanguage: pref}` to the service worker. A reload would drop the panel port while UI tool calls may be in flight: the SW re-parks calls already dispatched to the disconnected panel (`src/js/worker/120-tool-routing.js:286-290`) and rejects them when no result arrives within `REDISPATCH_RECONCILE_TTL_MS` = 30 s (`:64-67`), so a reload mid-call would fail that call. Views must therefore render translated text from state in their render functions; don't cache translated strings.
- **`refreshI18nViews()`** (ui/245) re-renders the current view (home, settings, dashboard, skills, docs, history, documents), the chat list, the button states, the action placements and the model display, and ends with `applyI18n(document)` over the fresh markup. It does **not** re-render the chat message list: `renderMessages` is not called there, because a new message-render call site raises the build's write-site ratchet (`build/write-site-ratchet.json`, the build aborts). Messages pick up the new language on their next render, e.g. when you navigate back to a chat.
- **Service worker:** `src/js/worker/190-entry.js` runs `i18nInit()` (IDB `uiLanguage`) at startup. `src/js/worker/130-port-bridge.js` handles `'ui-language'` with `i18nInit({language: msg.uiLanguage})`: the message carries the preference, so no IDB re-read can race the page's write. Before each agent run it also re-runs `i18nInit()` (IDB preference), so SW-side `t()` and the next system prompt follow a switch.

## 5. Right-to-left (ar, he)

- `i18nDir()` returns `'rtl'` and `<html dir="rtl">` is set at first paint and on every switch.
- CSS uses logical properties (`margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start`…). Direction-specific overrides live in `src/css/26-rtl.css`, scoped to `[dir="rtl"]`. Don't add physical `left`/`right` rules in new CSS.
- In JS, layout offsets (start/end) must be direction-aware (`i18nDir() === 'rtl'`); pointer coordinates (`clientX`, `style.left` of a cursor-anchored popup) stay physical.

## 6. Agent reply language

- `i18nResponseLanguageInstruction()` returns `''` for English, otherwise e.g. *"The user's interface language is French (Français). Reply in French unless the user writes in another language or asks otherwise. Keep code, identifiers, table/field names, sys_ids and tool arguments unchanged."*
- **Default system prompt:** the `{{RESPONSE_LANGUAGE}}` placeholder sits on the line after `CURRENT DATE` in `DEFAULT_SYSTEM_PROMPT_TEMPLATE` (core/110) and is filled by `expandSystemPromptPlaceholders`. For English its line is removed, so the English prompt is byte-identical to the pre-i18n one.
- **Custom system prompts:** put `{{RESPONSE_LANGUAGE}}` where you want it. Without it, `_maybeAppendResponseLanguage` (core/100, called by `getSystemPromptWithContext` before the sub-agent preamble) appends the instruction once: idempotent, and a no-op for English.
- Everything else the model reads stays English (see rule 2 below); `CURRENT DATE` stays en-US.

## 7. What to translate: extraction rules

1. **Only user-visible text:** HTML text and attributes, `textContent` / `title`, toasts (`showSnackbar`), dialogs (`showConfirmModal`, `showModal`, `showPromptModal`, `confirm`), menus, empty states, `document.title`, `chrome.notifications` text.
2. **LLM-facing text stays English:** tool definitions and `TOOL_SHORT_DESCRIPTIONS` (core/080), the system prompt (core/110, except `{{RESPONSE_LANGUAGE}}`), core/078, 097, 040, 140, `skills/**`, tool results and `error:` / `message:` result strings, hook prompts, `[WIDGET MODE]`; also throw messages, console logs and stored values.
3. **Markers and comparisons stay English in logic;** translate only the display (e.g. `'New Chat'`, `'Untitled Document'`, provider IDs). Label maps that also feed the model use `N_()` plus `t()` at display.
4. **Whole sentences:** one `t()` per sentence with `{placeholders}`, punctuation inside, no concatenated fragments.
5. **Plurals:** hand-rolled `n === 1 ? … : …` becomes `tn()`.
6. **Escaping:** keep the existing escaping; escape params exactly as the original escaped the dynamic parts; no raw `t()` output inside JS string literals of inline `on*=` handlers.
7. **Keys:** plain single- or double-quoted literals only.
8. **Keep as-is inside strings:** ServiceNow, AppAgent, GitHub, ATF, PR, sys_id, MID Server, Flow Designer, and table/field names.
9. **Dates and numbers:** `toLocale*()` becomes `i18nFormat*`; UI "ago" text becomes `i18nFormatRelative`; model-facing "ago" strings stay.
10. **Inline `left`/`right` styles set from JS:** direction-aware when they are layout (start/end), physical when they are pointer coordinates.
11. **Tests:** English is the identity, so English assertions keep passing; run the full suite.

## 8. Pitfall: a local `t` / `tn` shadows the globals

`t` and `tn` are globals. A local with the same name (a callback parameter `function(t)`, `var t = …`, `for (var t …)`, a destructured `t`) shadows them: `t('Save')` inside that scope calls the local, which fails at runtime only on that code path ("t is not a function") or returns garbage. Before wrapping a string, check the enclosing scopes and **rename the local** (`tab`, `tool`, `tok`…), never the global.

```js
tools.forEach(function(t) { row.title = t('Enabled'); });        // Wrong: the parameter shadows t()
tools.forEach(function(tool) { row.title = t('Enabled'); });     // Right
```

## 9. Adding a language or updating a catalog

1. Add `{ code, name, nativeName, dir }` to `I18N_LANGUAGES` (core/025); map regional tags in `resolveI18nLanguage` if needed. The Settings picker, `i18nDir()` and the `[dir="rtl"]` CSS pick it up automatically.
2. Create `src/locales/<code>.json`: one flat object `{ "English source": "translation" | { "one": "…", "other": "…" } }`. Plural objects use the target's CLDR categories and need `other`.
3. Keep `{placeholders}` byte-identical, keep the rule-8 terms untranslated, and use a consistent register (e.g. de "Sie", fr "vous").
4. Validate against the extracted sources with `checkCatalog`. Ship with **0 `placeholderMismatch`**, and review `missing` / `extra`:

```js
// Node, from the repo root
const fs = require('fs'), path = require('path');
const X = require('./build/i18n-extract.js');
const files = {};
(function walk(d) {
  for (const f of fs.readdirSync(d)) {
    const p = path.join(d, f);
    if (fs.statSync(p).isDirectory()) walk(p);
    else if (/\.(js|html)$/.test(f)) files[p.split(path.sep).join('/')] = fs.readFileSync(p, 'utf-8');
  }
})('src');
const sources = X.extractI18nStrings(files);   // [{source, refs, plural?}], plus sources.nonLiteral
const report = X.checkCatalog(sources, JSON.parse(fs.readFileSync('src/locales/fr.json', 'utf-8')));
console.log(report.missing.length, report.extra.length, report.placeholderMismatch);
```

In the extension sandbox, `await runFile('build/i18n-extract.js')` (js_eval) or `run_js_file` in module mode returns the same functions; read sources with `loadFile(path)`.

5. Nothing else to register: both builds copy `src/locales/*.json` to `locales/` (`build/build.js` and `skills/extension-dev/build.js`; a missing `src/locales/` just means English only).

## 10. Tests

- `loadModules` / `runFile` (`test/harness.js`, `test/ui-helpers.js`) auto-include the real i18n core with no catalog, so `t()` / `tn()` / `N_()` / `i18nFormat*()` are the English identity and need no stubs.
- Opt out per call with `{ i18n: false }`, e.g. to test a `typeof`-guarded fallback. The auto-include is also skipped when the paths already list `src/js/core/025-i18n.js` or `globals` stub an i18n name.
- To test a translated render inside the loaded namespace: `m.i18nSetCatalog('fr', { … })`, then `await m.i18nInit({ language: 'fr', browserLanguages: ['fr-FR'] })` (no fetch happens when the catalog is already set).
- Service-worker code (core/*, worker/*) may only call functions that are shared or declared in the SW bundle; guard page-only functions with `typeof X === 'function'`.
