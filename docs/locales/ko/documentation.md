# 시작하기 {#getting-started}

AppAgent는 Chrome 확장 프로그램으로 실행되는 ServiceNow용 AI 에이전트입니다. 필요한 작업을 평소 쓰는 말로 설명하면 에이전트가 데이터를 조회하고, 레코드를 편집하고, 앱과 위젯을 만들고, 브라우저에서 페이지를 테스트한 뒤 결과를 알려 줍니다.

:::tip
**빠른 시작:** 모델을 설정하고 ServiceNow 인스턴스 탭을 연 다음, 채팅에 요청을 입력하고 <kbd>Enter</kbd> 키를 누르세요.
:::

## 모델 설정 {#guide-setup}

1. [설정](app:openSettingsPageView)을 열고 **API 공급자**로 이동합니다
2. API 키를 사용해 공급자(Anthropic, OpenRouter 또는 OpenAI 호환 사용자 지정 API)를 추가합니다. 또는 Anthropic 공급자에서 **OAuth**를 켜고 Claude 계정으로 로그인할 수도 있습니다
3. **에이전트 모델**에서 사용할 모델을 선택합니다

API 키는 브라우저에만 저장됩니다. AI 호출은 브라우저에서 공급자로 직접 전송됩니다.

## 인스턴스 연결 {#guide-instances}

AppAgent는 같은 Chrome 프로필에서 열려 있는 **모든 ServiceNow 인스턴스를 자동으로 감지**하므로 연결 문자열을 입력할 필요가 없습니다. 일반 탭에서 인스턴스에 로그인하면 에이전트가 사용자의 역할과 접근 권한으로 해당 인스턴스에서 작업할 수 있습니다. *"인스턴스 목록 보여 줘"*라고 요청하면 감지된 모든 인스턴스, 내 역할, 연결 상태를 확인할 수 있습니다.

각 인스턴스에는 인스턴스 드롭다운에서 선택하는 **권한 수준**이 있습니다.

- **수동** — 모든 쓰기 작업(생성, 업데이트, 삭제, 양식 입력)을 직접 승인합니다
- **자동** — 에이전트가 묻지 않고 쓰기 작업을 결정합니다
- **개발** — 승인이 전혀 없습니다. 이 인스턴스의 모든 도구 호출이 묻지 않고 실행되므로 개발 인스턴스에서만 사용하세요

읽기는 항상 허용됩니다. 더 세밀하게 제어하려면 [도구 권한](#feature-permissions)을 참고하세요.

## 채팅 시작 {#guide-chat}

1. 사이드바에서 **새 채팅**을 클릭합니다 [새 채팅 시작 →](app:startNewChat)
2. 요청을 입력합니다. 예: *"오늘 생성된 인시던트를 모두 보여 줘"*
3. <kbd>Enter</kbd> 키를 눌러 보냅니다
4. 에이전트의 작업 과정을 지켜보세요. 각 도구 호출이 채팅에 표시되고, 확인이 필요한 단계에서는 승인 요청이 나타납니다

에이전트가 작업하는 중에도 계속 입력할 수 있습니다. 새 메시지를 보내면 현재 단계가 중단되고, **일시 중지**를 누르면 실행이 멈춥니다.

## 이미지 및 파일 첨부 {#guide-images}

1. 입력 영역의 **파일 첨부** 버튼을 클릭해 이미지, PDF, CSV 또는 텍스트 파일을 추가합니다
2. 또는 클립보드에서 이미지를 붙여 넣거나 채팅으로 끌어다 놓습니다
3. 첨부 파일에 대한 질문을 입력합니다

:::tip
오류 스크린샷, UI 목업 또는 내보낸 데이터를 첨부하면 에이전트가 사용자가 보는 화면을 그대로 확인할 수 있습니다.
:::

# 주요 기능 {#features}

## 채팅 {#page-chat}

기본 대화 화면입니다. [새 채팅 시작 →](app:startNewChat)

- **메시지 영역** — 도구 호출과 그 결과를 포함한 대화 내용
- **입력 상자** — 메시지를 입력하고 파일을 첨부합니다. 에이전트가 작업하는 중에 보내면 작업이 중단됩니다
- **일시 중지 / 계속 / 다시 시도** — 에이전트를 멈추거나, 재개하거나, 마지막 단계를 다시 시도합니다
- **컨텍스트 표시기** — 대화가 얼마나 찼는지 보여 줍니다. 클릭하면 요약해서 새 채팅으로 이어 갑니다
- **답변 카드** — 답변 아래에 **요약** 카드와 **링크** 카드(레코드, PR, 문서)가 표시될 수 있습니다
- **채팅 헤더** — 채팅 이름을 바꾸거나 고정하고, **전체 페이지로 확장**으로 AppAgent를 브라우저 탭 전체 화면으로 엽니다

## 브라우저 제어 {#feature-browser}

에이전트는 인스턴스의 브라우저 탭을 열고 제어하여 페이지를 확인하고 테스트할 수 있습니다.

- **이동, 클릭, 입력, 선택** — 실제와 같은 이벤트를 사용하므로 양식과 자동 완성 필드가 직접 입력한 것처럼 동작합니다
- **대기** — 지연 시간을 추측하지 않고 요소, 텍스트 또는 URL이 나타날 때까지 기다립니다
- **스크린샷** — 페이지, 위젯 또는 단일 요소를 캡처해 시각적으로 확인합니다
- **검사** — 요소 속성, 스타일, 콘솔 오류, 네트워크 요청을 읽습니다
- **가장** — 다른 사용자로 테스트한 뒤 다시 원래 사용자로 돌아옵니다

## 레코드 편집 및 버전 기록 {#feature-history}

에이전트가 인스턴스에서 수행한 모든 변경 사항은 채팅 사이드바에서 추적됩니다.

- **실행 취소** — 개별 변경 사항을 되돌립니다
- **다시 실행** — 되돌린 변경 사항을 복원합니다
- **XML 다운로드** — 모든 변경 사항을 내보냅니다. 예를 들어 다른 인스턴스로 옮길 때 사용합니다

## 하위 에이전트 {#feature-subagents}

작업량이 많거나 병렬로 처리할 작업이 있으면 에이전트가 **하위 에이전트**를 시작할 수 있습니다. 하위 에이전트는 자체 채팅과 컨텍스트에서 실행되는 백그라운드 작업자로, 작업이 끝나면 기본 채팅에 짧은 결과를 보고합니다.

- **모델 티어** — 각 하위 에이전트는 **small**, **medium**, **large** 티어 중 하나로 실행되며, **same**을 선택하면 상위 에이전트의 모델을 사용합니다. 티어별 모델은 [설정](app:openSettingsPageView) → **하위 에이전트 모델 티어**에서 지정합니다
- **작업자 표시줄** — 실행 중인 하위 에이전트가 채팅 입력란 위에 실시간 칩으로 표시됩니다. 칩을 열면 진행 상황을 보거나 대화 기록을 읽을 수 있습니다
- **풀** — 동시에 실행되는 하위 에이전트 수에는 상한이 있으며, 초과분은 대기열에서 기다립니다

## 대시보드 및 위젯 {#page-dashboard}

에이전트가 만든 대화형 위젯을 모아 두는 대시보드입니다. [대시보드 열기 →](app:openDashboardView)

1. **위젯 추가**를 클릭합니다
2. 원하는 내용을 설명합니다. 예: *"우선순위별 미해결 인시던트 차트"*
3. 에이전트가 위젯을 만듭니다. 언제든지 수정을 요청하거나 **다시 생성**을 클릭할 수 있습니다

위젯은 인스턴스에서 실시간 데이터를 가져오므로 항상 최신 상태를 유지합니다. 위젯을 끌어서 옮기거나, 크기를 조정하거나, 가져오고 내보낼 수 있습니다([고급](#advanced) 참고). 에이전트가 채팅에 인라인으로 표시한 위젯은 **대시보드에 고정**로 저장할 수 있습니다.

## 스마트 문서 {#page-documents}

**스마트 문서**는 에이전트가 작성하고 업데이트하는 영구적인 버전 관리 Markdown 문서로, 계획, 보고서, 사양, 조사 결과 등에 사용됩니다. 채팅에 인라인으로 표시되고, 모든 버전이 보관되며, 직접 편집할 수도 있습니다. 사이드바의 **문서**에서 열 수 있습니다. [문서 열기 →](app:openDocumentsView)

## 스킬 {#page-skills}

스킬은 에이전트에 추가 지식과 도구를 제공합니다. [스킬 열기 →](app:openSkillsView)

- **활성화 / 비활성화** — 스킬을 켜거나 끕니다. 필요 없는 스킬을 비활성화하면 답변의 초점이 흐려지지 않습니다
- **새 스킬** — Markdown으로 직접 스킬을 작성하거나 **에이전트로 편집**을 사용합니다
- **가져오기 / 내보내기** — 스킬을 폴더 단위로 공유합니다
- **스킬 작업** — 일부 스킬은 홈 페이지에 미리 정의된 워크플로를 시작하는 원클릭 버튼을 추가합니다

스킬은 **지식**(지침, 모범 사례)과 **사용자 지정 도구**(격리된 샌드박스에서 실행되는 JavaScript 함수)를 제공할 수 있습니다.

## 워크스페이스 및 GitHub {#feature-workspace}

각 채팅에는 **워크스페이스**가 있습니다. 에이전트가 파일을 읽고, 쓰고, 편집하고, 차이를 비교할 수 있는 파일 공간입니다.

- **GitHub** — [설정](app:openSettingsPageView)에서 GitHub 계정을 연결하면 리포지토리를 워크스페이스로 복제할 수 있습니다. 에이전트는 채팅에서 브랜치를 만들고, 커밋을 푸시하고, 풀 리퀘스트를 열 수 있습니다
- **풀 리퀘스트** — 채팅에서 연 PR은 채팅 사이드바에 **병합** 버튼과 함께 표시됩니다
- **채팅 간 보호** — 각 파일은 어떤 채팅이 변경했는지 기억하므로, 두 채팅이 동시에 작업해도 서로의 작업을 모르게 덮어쓰지 않습니다
- **자동 동기화** — 복제된 워크스페이스는 페이지를 이동하거나, 채팅을 전환하거나, 탭으로 돌아올 때 GitHub와 동기화됩니다

## 채팅 사이드바 {#feature-sidebar}

오른쪽 사이드바에는 현재 채팅에서 만든 모든 결과가 모입니다.

- **풀 리퀘스트** — 제목, 대상 브랜치, **병합** 버튼
- **워크스페이스 파일** — 파일을 열어 내용을 보거나, 차이를 확인하거나, 이전 버전을 살펴봅니다
- **버전 기록** — **실행 취소**, **다시 실행**, **XML 다운로드**가 포함된 인스턴스 변경 사항
- **작업자** — 실행 중이거나 완료된 하위 에이전트와 도구 호출, 편집한 파일, 연 PR 개수

## 작업 및 실시간 진행 상황 {#feature-actions}

오래 걸리는 작업도 조용히 멈춰 있지 않고 진행 상황을 실시간으로 보여 줍니다.

- **진행 카드** — 색상으로 구분된 상태(실행 중, 막힘, 완료, 오류)와 단계 목록이 담긴 하나의 카드
- **작업 버튼** — 후속 워크플로를 시작하는 원클릭 버튼
- **실행 중 표시** — 채팅 목록에서 에이전트가 작업 중인 채팅을 표시합니다
- **"에이전트 완료" 알림** — 실행 중에 다른 탭이나 창으로 전환하면 에이전트가 작업을 마쳤을 때 데스크톱 알림으로 알려 줍니다

## 활성 채팅 및 작업 {#feature-jobs}

헤더의 작업 필을 누르면 채팅과 백그라운드 작업을 실시간으로 볼 수 있습니다.

- **활성 채팅** — 실행 중인 채팅과 읽지 않은 결과가 있는 채팅(**굵게** 표시)이며, 각각 컨텍스트 사용량 링이 함께 표시됩니다
- **하위 에이전트** — 상위 채팅 아래에 표시됩니다. 열어서 대화 기록을 읽을 수 있습니다
- **펼치기** — 목록을 열 또는 섹션 레이아웃의 더 큰 패널로 엽니다

## 도구 권한 {#feature-permissions}

인스턴스별 권한 수준(**수동**, **자동**, **개발**) 외에도 각 도구에는 [설정](app:openSettingsPageView) → **도구 권한**에 자체 설정이 있습니다.

- **허용** — 도구가 항상 묻지 않고 실행됩니다
- **자동** — 에이전트가 확인이 필요하다고 표시한 호출이 아니면 묻지 않고 실행됩니다
- **묻기** — 호출할 때마다 승인 요청이 표시됩니다
- **끔** — 에이전트가 이 도구를 사용할 수 없습니다

일부 도구는 더 세밀하게 제어할 수 있습니다. ServiceNow API는 HTTP 메서드(GET, POST, PUT, PATCH, DELETE)별로, 브라우저 제어는 동작(이동, 클릭, 입력, 가장…)별로, 스킬 관리는 동작별로 설정할 수 있습니다. 확인 대화 상자는 위험도에 따라 색상으로 구분됩니다: **파란색**(일상 작업), **주황색**(주의), **빨간색**(파괴적 작업).

:::tip
DELETE 및 기타 파괴적 작업은 **묻기**로 유지하고, **개발**은 개발 인스턴스에서만 사용하세요.
:::

## 에이전트 도구 {#feature-tools}

에이전트가 사용하는 주요 도구는 다음과 같습니다.

| 도구 | 기능 |
|------|--------------|
| **ServiceNow API** (`servicenow_api`) | 레코드 읽기, 생성, 업데이트, 삭제 |
| **백그라운드 스크립트** (`servicenow_run_script`) | 인스턴스에서 서버 측 스크립트 실행(admin 역할 필요) |
| **스크립트 편집** (`servicenow_diff_edit`) | 정확한 검색 및 바꾸기 편집으로 스크립트 변경 |
| **브라우저 제어** (`iframe_tool`) | 브라우저 탭에서 이동, 클릭, 입력, 검사, 가장 |
| **브라우저 코드** (`js_eval`) | 다른 도구를 호출할 수 있는 격리된 샌드박스에서 JavaScript 실행 |
| **스크린샷** (`take_screenshot`) | 페이지, 위젯 또는 요소 캡처 |
| **위젯 및 카드** (`html_widget`, `display`) | 채팅에 대화형 위젯, 표, 카드, 타임라인 표시 |
| **스마트 문서** (`document`) | 영구 Markdown 문서 생성 및 업데이트 |
| **사용자에게 묻기** (`prompt_user`) | 인라인 양식으로 사용자 입력 요청 |
| **하위 에이전트** (`spawn_sub_agent`) | 백그라운드 작업자에 작업 위임 |
| **워크스페이스** (`workspace`) | 파일 및 GitHub 리포지토리 작업 |
| **웹 가져오기** (`web_fetch`) | 공개 웹 페이지 읽기 |
| **스킬** (`get_skill`, `manage_skill`) | 스킬 읽기 및 관리 |

[설정](app:openSettingsPageView) → **도구 권한**을 열면 모든 도구와 각 도구의 출처 및 권한을 확인할 수 있습니다.

## 대용량 콘텐츠 캐싱 {#feature-caching}

도구 결과가 대화에 넣기에 너무 크면(기본값 4K 토큰 초과) AppAgent가 결과를 캐시합니다. 에이전트는 개요를 받은 다음 필요한 부분만 읽고, 검색하고, 탐색합니다. 덕분에 채팅이 빠르고 초점을 유지합니다. 임계값(1K~100K 토큰)은 [설정](app:openSettingsPageView) → **대용량 콘텐츠 캐싱**에서 변경할 수 있습니다.

## 컨텍스트 표시기 {#feature-saturation}

채팅 입력란 옆의 **컨텍스트 표시기**는 대화가 얼마나 찼는지 보여 줍니다. 50%를 넘으면 에이전트는 작업을 마무리하고 남은 무거운 작업을 하위 에이전트에 넘기라는 요청을 받으며, 100%가 되면 멈추고 결과를 보고합니다. 언제든지 표시기를 클릭하면 대화를 요약해 새 채팅으로 이어 갈 수 있습니다.

## 사용량 및 속도 제한 {#feature-usage}

- **사용량 필** — 헤더에 API 사용량과 남은 한도가 표시됩니다. 클릭하면 자세한 내용을 볼 수 있습니다
- **자동 재시도** — 공급자가 속도 제한에 걸리거나 과부하 상태(HTTP 429 / 529)이면 AppAgent가 기다렸다가 자동으로 다시 시도하며, 채팅에 카운트다운을 표시합니다
- **크레딧 소진** — 429 오류가 실제로 크레딧 소진을 의미하는 경우 채팅에서 명확히 알려 줍니다

## 언어 {#feature-languages}

인터페이스는 영어와 24개 언어로 제공됩니다: 아랍어, 중국어(간체, 번체), 체코어, 덴마크어, 네덜란드어, 핀란드어, 프랑스어(프랑스, 캐나다), 독일어, 히브리어, 헝가리어, 이탈리아어, 일본어, 한국어, 노르웨이어, 폴란드어, 포르투갈어(브라질, 포르투갈), 러시아어, 스페인어, 스웨덴어, 태국어, 튀르키예어.

[설정](app:openSettingsPageView) → **언어** 또는 헤더의 빠른 설정 메뉴에서 선택하세요. **자동**은 브라우저 언어를 따르며, 지원되지 않으면 영어로 표시됩니다. 변경 사항은 새로 고침 없이 즉시 적용됩니다.

- **오른쪽에서 왼쪽** — 아랍어와 히브리어는 오른쪽에서 왼쪽 레이아웃을 사용합니다
- **현지 형식** — 날짜, 시간, 숫자가 선택한 언어의 형식을 따릅니다
- **에이전트 답변** — 다른 언어로 입력하지 않는 한 에이전트는 선택한 언어로 답변합니다. 코드, 테이블 이름, 필드 이름은 바뀌지 않습니다
- **이 도움말 페이지** — 선택한 언어로 표시되며, 변경 로그는 영어로 유지됩니다

# 문제 해결 및 FAQ {#faq}

### 에이전트가 내 인스턴스를 인식하지 못합니다

같은 Chrome 프로필의 탭에서 인스턴스를 열고 로그인되어 있는지 확인한 다음 *"인스턴스 목록 보여 줘"*라고 요청하세요. 그래도 표시되지 않으면 인스턴스 탭을 새로 고치세요.

### API 또는 인증 오류가 발생합니다

[설정](app:openSettingsPageView) → **API 공급자**에서 공급자의 API 키, 선택한 엔드포인트, 모델 이름을 확인하세요. OAuth를 사용하는 경우 같은 Chrome 프로필에서 claude.ai에 다시 로그인하세요.

### 에이전트가 속도 제한에 걸렸다고 합니다

AppAgent가 자동으로 다시 시도하며 카운트다운을 표시합니다. 계속 발생하면 사용량 필에서 남은 크레딧을 확인하거나, 하위 에이전트에 더 작은 모델 티어를 사용하세요.

### 승인 요청이 너무 많거나 너무 적습니다

인스턴스 드롭다운에서 인스턴스의 권한 수준(**수동**, **자동**, **개발**)을 변경하고, [설정](app:openSettingsPageView) → **도구 권한**에서 개별 도구를 조정하세요.

### 긴 채팅에서 답변이 느려지거나 정확도가 떨어집니다

대화의 컨텍스트가 가득 차고 있습니다. 컨텍스트 표시기를 클릭하면 요약과 함께 새 채팅에서 이어 갈 수 있습니다.

### 변경 사항을 되돌리려면 어떻게 하나요?

채팅 사이드바를 열고 버전 기록에서 해당 변경 사항의 **실행 취소**를 클릭하세요. **XML 다운로드**를 사용하면 모든 변경 사항을 내보낼 수 있습니다.

### 내 데이터는 어디에 저장되나요?

브라우저(IndexedDB)에 로컬로 저장됩니다. 채팅은 AppAgent 서버로 전송되지 않으며, AI 공급자와 ServiceNow 인스턴스로만 전송됩니다. [데이터 저장소](#adv-data-storage)를 참고하세요.

### 인터페이스나 이 페이지가 다른 언어로 표시됩니다

[설정](app:openSettingsPageView) → **언어**에서 언어를 선택하세요. **자동**은 브라우저 언어를 따릅니다.

## 위젯 크기 조정 및 이동 {#adv-resize-move}

**위젯 크기 조정:**

- 각 위젯의 오른쪽 아래 모서리에 **크기 조정 핸들**이 있습니다
- 핸들을 클릭하고 끌어서 위젯 크기를 조정합니다
- 너비는 12열 그리드에 맞춰집니다(최소 3열)
- 높이는 50px 단위로 측정됩니다(최소 2단위 = 100px)

**위젯 이동:**

- **헤더** 토글을 켜서 위젯 헤더를 표시합니다
- **위젯 아이콘**(끌기 핸들)을 클릭하고 끌어서 순서를 바꿉니다
- 위젯을 다른 위젯 위에 놓으면 위치가 서로 바뀝니다
- 위젯 순서는 자동으로 저장됩니다

## 가져오기/내보내기 형식 {#adv-import-export}

**대시보드 내보내기** (`dashboard-YYYY-MM-DD.json`):

```
{
  "type": "appagent-dashboard",
  "version": 1,
  "widgets": [
    {
      "id": "widget_123",
      "title": "Widget Title",
      "html": "<html>...</html>",
      "width": 6,
      "height": 8,
      "order": 0,
      "conversation": [...]
    }
  ]
}
```

**단일 위젯 내보내기:**

```
{
  "type": "appagent-dashboard-widget",
  "version": 1,
  "widget": { ... }
}
```

**단일 채팅 내보내기** (`chat-title-YYYY-MM-DD.json`):

```
{
  "exportType": "single_chat",
  "exportDate": "2024-01-15T10:30:00.000Z",
  "chat": {
    "id": "chat_123",
    "title": "Chat Title",
    "messages": [
      {
        "role": "user",
        "content": "User message text"
      },
      {
        "role": "assistant",
        "content": "Agent response text"
      }
    ],
    "createdAt": 1705312200000
  }
}
```

채팅 내보내기에는 모든 사용자 메시지와 에이전트 응답을 포함한 전체 대화 기록이 보존됩니다. 개별 채팅을 내보내려면 채팅 드롭다운 메뉴(···)에서 **다운로드**를 선택하세요.

**스킬 내보내기**(폴더 구조):

```
skill-name/
├── SKILL.md      # Main skill definition
├── sample.xml    # Optional XML assets
├── helper.js     # Optional JS assets
└── notes.md      # Optional MD assets
```

:::tip
**참고:** 스킬 가져오기/내보내기는 File System Access API를 사용하므로 **Chrome 또는 Edge 브라우저에서만 작동**합니다.
:::

**전체 데이터 내보내기** (`appagent-backup-YYYY-MM-DD.json`):

```
{
  "version": 3,
  "exportDate": "2024-01-15T10:30:00.000Z",
  "chats": [...],
  "settings": [...],
  "dashboardWidgets": [...],
  "apiProviders": [...]
}
```

전체 백업에는 모든 채팅 기록, 설정, 도구 권한, 대시보드 위젯, API 공급자 구성이 포함됩니다.

설정에서 켜면 에이전트가 응답할 때마다 API 통계가 표시됩니다.

| **캐시 읽기/쓰기** | 프롬프트 캐시에서 읽거나 캐시에 쓴 토큰(비용 절감) |
| **추론** | 내부 추론에 사용된 토큰(일부 모델) |
| **비용** | API 호출의 예상 비용(USD) |
| **소요 시간** | API 호출에 걸린 시간 |

여러 턴에 걸친 대화에서는 모든 호출의 합계가 집계 통계로 표시됩니다.

:::tip
API 통계 표시 여부는 [설정](app:openSettingsPageView) → 화면 → API 통계 표시에서 전환할 수 있습니다.
:::

## 스킬 직접 편집 {#adv-skills-manual}

스킬은 직접 만들고 편집하거나 에이전트의 도움을 받아 만들 수 있습니다.

**스킬 직접 만들기:**

1. [스킬](app:openSkillsView)로 이동해 **새 스킬**을 클릭합니다
2. 스킬 이름과 설명을 입력합니다
3. 스킬 내용을 Markdown 형식으로 작성합니다
4. **저장**을 클릭해 스킬을 만듭니다

**SKILL.md 형식:**

```
# Skill Name

Description of what this skill does.

## Instructions

Detailed instructions for the Agent...

## Examples

- Example usage 1
- Example usage 2
```

**에이전트로 편집:**

1. 원하는 스킬에서 **에이전트로 편집**을 클릭합니다
2. 원하는 변경 사항을 설명합니다
3. 에이전트가 스킬 내용을 수정합니다
4. 변경 사항을 검토하고 저장합니다

**스킬 자산:** 스킬에는 에이전트에 추가 컨텍스트나 코드를 제공하는 파일(XML, JS, MD)을 포함할 수 있습니다.

## 시스템 프롬프트 {#adv-system-prompt}

시스템 프롬프트는 에이전트의 동작과 기능을 정의합니다. [설정](app:openSettingsPageView)에서 사용자 지정할 수 있습니다.

**시스템 프롬프트 편집:**

1. 설정 → 시스템 프롬프트 섹션으로 이동합니다
2. **편집**을 클릭해 편집 모드로 전환합니다
3. 필요에 따라 템플릿을 수정합니다
4. **저장**을 클릭해 변경 사항을 적용합니다

**사용 가능한 자리 표시자:**

| 자리 표시자 | 설명 |
|-------------|-------------|
| `{{CURRENT_DATE}}` | 오늘 날짜(요일, 월, 일, 연도) |
| `{{ORCHESTRATOR_POLICY}}` | 하위 에이전트 위임 정책 — 기본 채팅에는 포함되고 하위 에이전트 채팅에서는 비워집니다 |
| `{{DISABLED_TOOLS}}` | 비활성화된 도구 목록 |
| `{{TOOL_CATALOG}}` | 지연 로드 도구 카탈로그(지연 도구 로딩이 꺼져 있으면 비어 있음) |
| `{{SKILLS_SUMMARY}}` | 활성 스킬 내용 |

자리 표시자는 AI로 보낼 때 실제 값으로 자동 대체됩니다. 토큰 수 표시에는 템플릿 크기와 확장된 크기가 모두 표시됩니다.

:::tip
필요하면 **기본값으로 되돌리기**를 클릭해 원래 시스템 프롬프트를 복원하세요.
:::

## 에이전트 API 호출 {#adv-agent-api}

AppAgent는 **Chrome 확장 프로그램**으로 실행됩니다.

- AI API 호출은 **브라우저에서 AI 공급자로 직접** 전송됩니다(예: Anthropic, OpenRouter)
- 인스턴스나 AppAgent 서버를 **거치지 않습니다**
- API 키(또는 OAuth 토큰)는 브라우저에 로컬로 저장됩니다
- 대화 데이터는 처리를 위해 AI 공급자로 전송됩니다

**작동 방식:**

1. 채팅에 메시지를 입력합니다
2. AppAgent가 시스템 지침, 도구, 대화 기록으로 프롬프트를 구성합니다
3. 프롬프트가 AI 공급자의 API로 전송됩니다
4. 에이전트의 응답이 브라우저로 스트리밍됩니다
5. 도구 호출은 브라우저에서 실행되며, API 호출에는 인스턴스 세션이 사용됩니다

:::tip
**개인 정보 보호:** API 키와 대화 데이터는 클라이언트 측에서 처리됩니다. 인스턴스와 상호 작용하는 도구 호출은 기존 세션 자격 증명을 사용합니다.
:::

## LLM 엔드포인트 {#adv-endpoints}

모델은 재사용 가능한 `URL + API key` 쌍인 **이름이 지정된 LLM 엔드포인트**를 통해 연결됩니다. 이를 통해 AppAgent를 OpenRouter, 로컬 게이트웨이, 프록시 또는 직접 호스팅하는 모델 등 **모든 OpenAI 호환 채팅 완성 API**에 연결할 수 있습니다.

1. [설정 → LLM 엔드포인트](app:openSettingsPageView)에서 **엔드포인트 추가**를 클릭합니다
2. 이름, API URL, API 키를 입력합니다
3. 각 모델(API 공급자)은 엔드포인트를 하나 선택합니다. 키를 한 번만 업데이트하면 해당 엔드포인트를 사용하는 모든 모델에 반영됩니다

:::tip
Claude **OAuth** 공급자는 엔드포인트를 사용하지 않고 `api.anthropic.com`과 직접 통신합니다.
:::

## Claude로 로그인(OAuth) {#adv-oauth}

API 키를 붙여 넣는 대신 기존 claude.ai 세션으로 Anthropic 공급자에 로그인할 수 있습니다.

1. [설정 → API 공급자](app:openSettingsPageView)에서 Anthropic 공급자를 추가하거나 편집하고 **OAuth**를 켭니다
2. 확장 프로그램이 같은 Chrome 프로필의 claude.ai 로그인 정보를 사용해 Anthropic에 직접 연결합니다
3. 별도의 로그인 창이 없고, 중간에 AppAgent 서버도 거치지 않습니다

**요구 사항:**

- 같은 Chrome 프로필에서 `claude.ai`에 로그인되어 있어야 합니다
- SSO(Single Sign-On) 계정에서도 작동합니다

:::tip
OAuth 토큰은 자동으로 갱신됩니다. 로그인에 실패하면 같은 프로필에서 `claude.ai`를 열고 다시 로그인하세요.
:::

## 보안 고려 사항 {#adv-security}

**API 키 저장:**

- **API 키는 브라우저의 IndexedDB에 로컬로 저장**됩니다
- 키는 인스턴스나 AI 공급자 이외의 서버로 전송되지 않습니다
- 브라우저 데이터를 지우면 저장된 API 키도 삭제됩니다

**세션 및 권한:**

- 에이전트는 **현재 사용자 세션**으로 실행되며 사용자의 접근 권한과 역할을 그대로 이어받습니다
- 인스턴스에 대한 모든 API 호출은 사용자의 세션 자격 증명을 사용합니다
- 에이전트는 사용자 계정이 접근할 수 있는 항목에만 접근할 수 있습니다

**도구 실행 환경:**

- **브라우저 코드(js_eval)**는 `executeTool()` 접근 권한만 있는 **격리된 샌드박스**에서 JavaScript를 실행합니다
- **위젯 스크립트**는 API 호출용 `executeTool()` 접근 권한만 있는 **격리된 iframe**에서 실행됩니다
- **스킬 도구**는 `executeTool()` 접근 권한만 있는 **격리된 샌드박스**에서 실행됩니다
- 모든 API 접근은 `executeTool("servicenow_api", {...})`를 통해 **권한 시스템**을 거칩니다
- 에이전트는 ServiceNow 인스턴스의 **브라우저 탭**에서 페이지와 상호 작용합니다

**레코드 수정 기능:**

- **ServiceNow API** 도구는 레코드를 변경할 수 있는 POST, PATCH, PUT, DELETE 메서드를 지원합니다
- 입력 및 클릭 도구 권한이 주어지면 에이전트는 **통합 브라우저**를 통해 레코드를 만들고 편집할 수 있습니다
- [도구 권한](app:openSettingsPageView)을 구성해 승인이 필요한 작업을 제어하세요

**자기 개선:**

- 에이전트는 스킬을 만들고, 편집하고, 활성화하는 등 **자체 스킬을 관리**할 수 있습니다
- 이를 통해 에이전트는 시간이 지나면서 학습하고 스스로 개선할 수 있습니다
- 스킬 변경 사항이 기대에 맞는지 정기적으로 검토하세요

## 데이터 저장소 {#adv-data-storage}

AppAgent는 **IndexedDB**를 사용해 브라우저에 데이터를 로컬로 저장합니다.

| 데이터 유형 | 저장소 | 설명 |
|-----------|---------|-------------|
| **채팅** | IndexedDB | 모든 대화 기록, 메시지, 도구 결과 |
| **설정** | IndexedDB | 도구 권한, API 키, 모델 기본 설정 |
| **대시보드 위젯** | IndexedDB | 위젯 HTML, 제목, 크기, 대화 기록 |
| **스킬** | IndexedDB | 스킬 정의, 내용, 자산 |
| **API 공급자** | IndexedDB | 사용자 지정 API 공급자 구성 및 엔드포인트 |
| **UI 상태** | localStorage | 사이드바 상태, 현재 보기, 스크롤 위치 |

**데이터 다운로드:**

1. [설정](app:openSettingsPageView) → 데이터 관리로 이동합니다
2. **데이터 내보내기**를 클릭합니다
3. JSON 백업 파일이 다운로드됩니다

**데이터 삭제:**

1. [설정](app:openSettingsPageView) → 데이터 관리로 이동합니다
2. **모든 데이터 삭제**를 클릭합니다
3. 두 번 확인하면 모든 데이터가 영구적으로 삭제됩니다

:::tip
**중요:** 데이터는 확장 프로그램에 로컬로 저장됩니다. 브라우저 데이터를 지우거나, 확장 프로그램을 제거하거나, 다른 브라우저 프로필을 사용하면 데이터 저장소가 분리됩니다.
:::
